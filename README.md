# Glean server-side event collection examples

End-to-end demonstrations of server-side Glean telemetry on GCP, covering two
ingestion paths:

1. **Cloud Logging path** (existing production approach for some services):
   server writes events to stdout → fluentbit ships them to Cloud Logging →
   a logging sink forwards to a Pub/Sub topic → the gcp-ingestion Decoder
   Dataflow (deployed with `--logIngestionEnabled=true`) parses LogEntry
   wrappers and writes to BigQuery.
2. **Direct Pub/Sub path** (DENG-9533, work in progress): server publishes
   directly to a Pub/Sub topic with ping metadata as message attributes and
   the gzipped Glean ping JSON as message body. The Decoder Dataflow
   (deployed with `--directPubsubEnabled=true`) stamps `submission_timestamp`
   from `publishTime` and writes to BigQuery. Bypasses the fluentbit / Cloud
   Logging hop.

The Cloud Logging examples cover JS, TS, Go, Python, and Rust loggers; the
direct-Pub/Sub example is currently Go-only (`test-go-publisher`).

## Repository layout

| Path | Path type | What it is |
|---|---|---|
| `test-js-logger`, `test-ts-logger`, `test-go-logger`, `test-py-logger`, `test-rust-logger` | Cloud Logging | Minimal per-language loggers using glean_parser's stdout output. |
| `test-go-publisher` | Direct Pub/Sub | Reference implementation: stateless message builder (autogenerated by glean_parser) + forkable `publisher.go` covering lifecycle / batching / metrics. See [`test-go-publisher/README.md`](test-go-publisher/README.md). |
| `java-consumer` | Either | Reads decoded messages from a Pub/Sub subscription; useful for sanity checks. |
| `kubernetes/` | Either | Kubernetes manifests for deploying the loggers / publisher to a GKE cluster. |
| `kubernetes-engine-customize-fluentbit/` | Cloud Logging | GKE fluentbit configuration used by the Cloud Logging path. |
| `ingestion-beam-decoder-streaming.sh` | Either | Wrapper for submitting a Decoder Dataflow job (works for both `--logIngestionEnabled` and `--directPubsubEnabled` modes; edit flags accordingly). |
| `ingestion-beam-decoder.sh` | Cloud Logging | Wrapper for the batch (BigQuery → BigQuery) Decoder, used for backfills. |
| `alternative-batch-decoding.md` | Cloud Logging | Design notes on a batch-decoding alternative. |

## Running locally

### Cloud Logging path

```bash
cd test-js-logger && nvm use 18.14.2 && npm start
# or
cd test-go-logger && go run main.go
# or
cd test-py-logger && python main.py
```

These print Glean ping events to stdout in the format expected by Cloud
Logging's structured-log parser.

### Direct Pub/Sub path

```bash
cd test-go-publisher
gcloud auth application-default login
go run . --project=$PROJECT_ID --topic=$TOPIC_ID --rate=10 --duration=30s
```

See [`test-go-publisher/README.md`](test-go-publisher/README.md) for the
template-vs-app split, observability, and the integration recipe.

## Deploying to GKE (sandbox)

The `kubernetes/` directory contains manifests for the
`akomar-server-telemetry-poc` project. Typical workflow per logger:

```bash
export project_id=akomar-server-telemetry-poc
export region=us-east1
gcloud config set project ${project_id}
gcloud config set compute/zone ${region}

docker build --platform linux/amd64 -t test-js-logger test-js-logger
docker tag test-js-logger gcr.io/${project_id}/test-js-logger
docker push gcr.io/${project_id}/test-js-logger
kubectl apply -f kubernetes/test-js-logger-deploy.yaml
```

Substitute the logger name for the other examples.

## Running the Decoder

The decoder lives in [mozilla/gcp-ingestion](https://github.com/mozilla/gcp-ingestion);
this repo just wraps the `mvn exec:java` invocation with sandbox-specific
flags.

```bash
cd ../gcp-ingestion
../glean-server-examples/ingestion-beam-decoder-streaming.sh
```

The script defaults to the direct-Pub/Sub flag set
(`--directPubsubEnabled=true`); edit it to swap in `--logIngestionEnabled=true`
for the Cloud Logging path.
