# test-go-publisher

:warning: work in progress, see https://github.com/mozilla/gcp-ingestion/pull/2857 and https://github.com/mozilla/glean_parser/pull/821

Reference implementation for the direct Pub/Sub Glean telemetry path
(DENG-9533). Publishes Glean events directly to a Pub/Sub topic that is
consumed by a Decoder Dataflow running with `--directPubsubEnabled=true`,
bypassing the Cloud Logging / fluentbit hop.

This example is intended to be forked and adapted, not depended on as a
library. The patterns here (lifecycle, batching, metrics) can eventually
move into a Go server Glean SDK; until then, server-side consumers copy
this file layout and tune to their workload.

## Architecture

The code is split into two halves:

| File | Owner | What it contains |
|---|---|---|
| `glean/server_events.go` | glean_parser (autogenerated) | `GleanEventsBuilder` and `Build<Ping>Message` methods. Glean-specific message shape, gzip, schema-driven ping construction. Stateless. |
| `publisher.go` | this example (reference impl) | Pub/Sub client + topic, batching settings, async result handling, Flush/Close shutdown, Prometheus metrics. This is the file to fork. |
| `main.go` | this example (test harness) | CLI flags, synthetic event generator, signal handling, periodic stats log. Demonstrates how the pieces are wired together. |

The split matters because lifecycle / transport concerns proved too varied
to live in a code-generation template.

## Wire format

Pub/Sub messages produced by `BuildEventsPingMessage`:

- Data: gzipped inner Glean ping JSON.
- Attributes (required): `document_namespace`, `document_type`,
  `document_version`, `document_id`.
- Attributes (optional): `user_agent`, `x_forwarded_for`.
- submission_timestamp: not set by the publisher. The Decoder stamps it
  from Pub/Sub's `publishTime`.

Wire-format contract is documented in
[`docs/architecture/decoder_service_specification.md`](https://github.com/mozilla/gcp-ingestion/blob/direct_pubsub/docs/architecture/decoder_service_specification.md)
in `mozilla/gcp-ingestion`.

## Regenerating `glean/server_events.go`

```bash
glean_parser translate metrics/metrics.yaml -f go_server_pubsub -o glean/
```

Requires glean_parser with the `go_server_pubsub` outputter (see
[glean_parser#821](https://github.com/mozilla/glean_parser/pull/821); to be
released once merged).

## Observability

`publisher.go` registers four Prometheus metrics on the default
registry via `promauto`:

| Metric | Type | Use |
|---|---|---|
| `glean_pubsub_publish_total{status}` | counter | Throughput by success/error |
| `glean_pubsub_publish_duration_seconds` | histogram | Latency of the synchronous `topic.Publish` call. Spikes here indicate publisher-side flow-control backpressure. |
| `glean_pubsub_result_duration_seconds` | histogram | End-to-end latency from publish call to Pub/Sub ack/error. Includes batching delay + network round-trip. |
| `glean_pubsub_inflight` | gauge | Messages currently awaiting result |

If your application already mounts `promhttp.Handler()` on `/metrics`
(serving the default registry), these four metrics show up there
automatically with no extra wiring.

`main.go` spins up a separate listener on `:2112` (configurable via
`--metrics-addr`) just so you can `curl /metrics` during a local run;
that listener is a test-harness convenience, not part of the reference
publisher. The test harness also logs a 10-second generator heartbeat to
stdout for kubectl-logs visibility.

## Running locally

```bash
# Authenticate against the target GCP project.
gcloud auth application-default login

go run . \
  --project=$PROJECT_ID \
  --topic=structured-direct \
  --rate=1000 \
  --duration=30s
```

Flags:

- `--project` / `PROJECT_ID` (required)
- `--topic` / `TOPIC_ID` (required)
- `--rate` / `EVENTS_PER_SEC` events/sec generated (default 1)
- `--duration` total run time, e.g. `30s`, `5m` (default 0 = infinite)
- `--metrics-addr` / `METRICS_ADDR` Prometheus listen address (default `:2112`)
- `--flush-timeout` max wait for in-flight publishes on shutdown (default 30s)

## End-to-end validation

Two paths, in order of cheapness:

1. `pstest` fake (in-process Pub/Sub server) for message-shape
   validation without GCP. Run with `go test ./...`. Validates required /
   optional attributes, gzip body shape, Flush draining, and the
   success/error metric paths. Doesn't validate against the real Decoder.
2. Sandbox project (`akomar-server-telemetry-poc` or equivalent) with a
   `structured-direct` topic and a Decoder Dataflow running with
   `--directPubsubEnabled=true`. Validates the full chain to decoded topic.
   To run publisher: `go run . --project=akomar-server-telemetry-poc --topic=glean-server-event-direct --rate=10 --duration=30s`
   To read decoded message: `gcloud pubsub subscriptions pull telemetry-decoded-inspect --project=akomar-server-telemetry-poc --limit=1 --auto-ack --format=json | jq -r '.[0].message.data' | base64 -d | gunzip | jq .`
   To check error topic: `gcloud pubsub subscriptions pull telemetry-error-inspect --project=akomar-server-telemetry-poc --limit=5 --auto-ack`


## How to integrate with your server

`main.go` is wrapped around a synthetic event generator, but the
publisher-relevant snippets are tagged. Search for `REFERENCE IMPL:` to
jump between them; line numbers below are approximate.

1. Fork `publisher.go` verbatim. Adjust `topic.PublishSettings`
   (`publisher.go:121-127`) to your throughput target.
2. Generate `glean/server_events.go` from your own `metrics.yaml`
   using the command in the section above.
3. At application startup, build one `GleanEventsBuilder` and one
   `Publisher`; share them across request handlers. Builder is stateless;
   Publisher is safe for concurrent `Publish`. See
   `main.go:73-85` (`// === REFERENCE IMPL: startup ===`).
4. At each event call site, build a ping message and hand it to the
   publisher. See `main.go:143-161`
   (`// === REFERENCE IMPL: per-event publish ===`).
5. At application shutdown, call `Publisher.Flush(ctx)` then
   `Publisher.Close()` to drain in-flight messages. See
   `main.go:90-108` (`// === REFERENCE IMPL: graceful shutdown ===`)
   for the recommended sequence wired to SIGINT/SIGTERM.
6. Metrics: no wiring needed if you already serve `promhttp.Handler()`
   on `/metrics` from the default registry (as MARS does at
   `cmd/mars/main.go`). The four `glean_pubsub_*` metrics register
   themselves on import and appear at your existing endpoint.
